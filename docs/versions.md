# Several game versions: the base version and the changes, step by step

**Where the versions come from:** the package server of BAR (rapid, `https://repos-cdn.beyondallreason.dev/byar/versions.gz`) has a package for **every commit** of the Beyond All Reason repository, `byar:git:<full hash>` = "Beyond All Reason test-<number>-<short hash>" (12,593 of them, back to test-11420; 455 in 2026 up to November, 333 of them on the branch `stable`, see [plan-versions-2026.md](plan-versions-2026.md)). The packages and their files stay on the server, so any version can be downloaded again and gives the same export: what the players had. `pr-downloader` of the BAR installation (`<BAR>/bin/pr-downloader.exe`, with the settings of the launcher) downloads a version into the data folder (only the files that are missing); the export then runs with `-Game "Beyond All Reason <version>"`. A package just downloaded is not in the archive cache of the installation yet: the tools then find it through the rapid lists of the data folder (`bar_common.rapid_package`, `Test-RapidPackage` in `export_units.ps1`); the engine adds it when it starts. Tried with test-31450 (2026-09-29) to test-31836: each starts with the installed engine (recoil 2026.07.04). The decisions for the whole year from 2026-01-01 (another base, the engine of each version, the prefilter, the status `checkedUpTo`) are in [plan-versions-2026.md](plan-versions-2026.md).

**New versions:** `update game versions.bat` (`exporter/update_versions.py`; `--list` only shows them, `--max N` takes only the first N, `--data` is passed to every tool) takes the versions of the server whose commit is on `stable` and dated 2026-01-01 or later (the clone `cache/bar.git`, `exporter/git_history.py`), and every one newer than `checkedUpTo` (`versions.json`), oldest first. A version for which Git shows no change of the unit files or the look (`git_history.py`: `VALUE_PATHS`, `LOOK_PATHS`) is not downloaded or started: `checkedUpTo` moves on (`--no-prefilter` exports every version). For every other version: the package (`pr-downloader`), the engine of its date (`exporter/engines.json`, made by `make_engine_table.py` from the history of BYAR-Chobby; the engines lie in `cache/engines/`, not in the installation), then `export_and_render_all_units.ps1 -Game <it> -Engine <engine> -Yes`: export, diff, the pictures that changed. If the engine differs from the one of the version before, that version is exported again with the new engine (`cache/control/`) and the diff is made against that export; units that differ only because of the engine are named in `engineOnly` of the version. The full export of every version is removed after it is done (`--keep-exports`). At the start `engines.json` is brought up to date (`make_engine_table.py`: a new standard engine of the launcher is picked up), and after exported versions `counterparts.json` and `counters.json` are refreshed from beyondallreason.info (`export_counterparts.py`, `export_counters.py`; only for `website/assets`; `--no-lists` skips it, a failure is a warning). A run that stops can be started again. A folder with another base is refused (`--out` new). The first run takes hours (about 230 exports).

**Base version:** the first version of the year (test-29183, 2026-01-01; before the year run: test-31820) keeps everything: the reduced file of all units and all pictures. **Every later version keeps only what changed against the version before it** (`exporter/reduce_units.py`; the version before = the base with the changes of every version in between): `units-<version>.diff.json.gz` (`before`: that version) with the units whose values (the reduced fields), picture or icon changed, the units that are new (both with their whole reduced entry) and the names of the units that are gone; `data/pictures.json` with the fingerprints of the changed pictures; in its `images/` only the pictures (and icons) that changed. **A version in which nothing changed gets no files** and is not shown; `versions.json` only moves `checkedUpTo` (the newest version looked at) on, so it is not compared again. Its full export stays local (`.gitignore`). Measured: test-31836 against test-31820: nothing the page shows changed (unchanged). A test chain (in a scratch folder, `update_versions.py --max 2`) from test-31450 as base: test-31465 (downloaded, it was not installed) 10 units changed against test-31450, 2 pictures and 1 icon, diff file 0.8 KB; test-31479 24 units against test-31465, 4 pictures, 1.4 KB; about 50 seconds per version (export 45 s, pictures a few seconds).

**A picture differs** if its **fingerprint** differs: an md5 over the md5 of the model file, the three textures (the pool knows the md5 of every file, nothing has to be read but the model), the pieces the script hides when the unit is created and the faction colour (`render_unit.picture_fingerprints`, the same inputs as the rendering). Of the script only the hidden pieces count: test-31836 changed the script of `legkark`, but not what it hides. The fingerprints are kept in `data/pictures.json` (of the base all, of a later version the changed ones), so a later version is compared without rendering anything; only the pictures that changed are rendered (`reduce_units.py --pictures <folder>` lists them for `export_and_render_all_units.ps1`). Without the game installed there are no fingerprints: then only the values are compared.

**Chance in the game:** the Scavenger loot boxes (`lootbox*`) get one of two models by chance at every start of the game (`unitbasedefs/lootboxes/lootboxnano.lua`: `math.random(1, 2)`): two exports of the same version differ there. Their pictures are not compared (`RANDOM_MODEL` in `reduce_units.py`).

**Date of a version:** the version name ends with the short hash of the commit of the Beyond All Reason repository it was built from (`test-31836-b250a16`); the date of that commit is the date in `versions.json`: read from the clone of the repository (`cache/bar.git`, `exporter/git_history.py`), without it from the GitHub API (`/repos/beyond-all-reason/Beyond-All-Reason/commits/<hash>`, which often answers with 503). The dates there are kept.

A renamed unit shows up as gone and new. A diff file depends on all files before it: if one in the middle is made again, the later ones have to be made again too. `reduce_units.py --redo <version folder>` makes only that version again (the export script does this for the version it has just exported, so a new export never rebuilds the chain), `--force` makes all of them again, from the full exports. A diff file made against another version than the one before it now is an error (`before` is checked); a version whose pictures were compared before and whose game is no longer installed is not made again without them (the fingerprints would be lost). If the base version is ever to be changed: make the new base's reduced file with everything (delete the old one, `--force`), then all diff files again. A version older than the base is left out.

**The year run (done 2026-11-13, [plan-versions-2026.md](plan-versions-2026.md) is the reasoning).** From the base test-29183 (2026-01-01) to test-31943 (2026-11-12): 339 versions of `stable`, of which Git showed no change of the unit or look files in 112 (skipped without a download or game start), 4 are broken game versions (skipped, named with the reason in `exporter/broken_versions.json`: test-29940 `raptor_unitdefs_post.lua`, test-30553 `modoptions.lua`, test-31732 `scavengers/weapondef_post.lua`, and the engine then crashes), and the rest was exported with the engine of its day (`exporter/engines.json`: 2025.06.12, 2025.06.19, 2025.06.24, 2026.06.11, 2026.06.12, 2026.07.04; about 7 engines of 24 MB each in `cache/engines/`). 64 versions are listed (the base and 63 with a diff file): 1306 changed units in total, 37 units gone. One difference came from the engine only (test-30637: the build time of `armcomboss`, an overflow that differs between engines), named in `engineOnly`. The run took about 2.5 hours (about 30 to 40 seconds per exported version, the pictures cost almost nothing), the result is 30 MB in about 2050 files, the history file 45 KB.

**A failure stops the run.** The game itself can be broken in a version (the definitions do not load; the log of the engine says `forced quit with exception`): `update_versions.py` prints that line and stops; if it is a mistake in the game, the version is named in `exporter/broken_versions.json` and the next run skips it (the next version is compared with the one before the broken one).
